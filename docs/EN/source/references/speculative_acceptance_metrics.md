# Optional speculative acceptance metrics

`--enable_spec_acceptance_metrics` enables request-local acceptance histograms in
normal serving mode. The flag is disabled by default. It is currently rejected
with prefill/decode disaggregation (PD), because the final metadata transport
does not span the prefill and decode roles.

For the native `/generate` endpoint, use `return_details=true`; the final token's
details contain `spec_acceptance_metrics`. For `/generate_stream`, the final server-sent event contains this field and the final native speculative-decoding counters. Statistics are
recorded from the existing verification results.

The histogram is indexed by the actual verification width and the accepted
draft prefix length. One verification also produces a target token. The first
decode after initial or recovered prefill is recorded as `bootstrap`, separately
from blocks generated by the drafter. Request slot reuse starts a fresh history.

For a fixed draft length, the mean acceptance length is
`1 + accepted_draft_tokens / proposals.rounds`, including one target token per
verification round. Per-position statistics use the following denominators:

- `accepted/proposed`: accepted-prefix survival at that position.
- `accepted/reached`: conditional acceptance after the earlier prefix survived.

These are verification metrics **before EOS and output-budget truncation**. They
are not a throughput measurement. Pipelined execution can also verify work
whose output is discarded when a request finishes. `visible_output_tokens`,
`inferred_output_tokens`, `verification_output_ranges`, and `committed` keep this
distinction explicit. The committed output length per contributing proposal
round is `committed.output_tokens/committed.proposal_rounds`. Rounds with no
visible output are counted in `committed.unused_proposal_rounds`.

The final counters and histogram share a release-time snapshot. HTTP may have
prepared the final token frame before an overlapping verification completed;
when this happens, `http_counter_snapshot` retains the earlier values for audit.
All three native speculative-decoding counters in the final response use the release-time values.
